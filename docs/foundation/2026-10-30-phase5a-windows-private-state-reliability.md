## Phase 5B objective, production contract and red-first repair

Objective: remove a demonstrated production-owned sharing conflict without treating the historical error-5 call site as a known syscall. Methods: inspected all direct production calls to `write_private_atomic`, the Windows owner/DACL verifier and locked tempfile Windows implementation; held a real production verifier handle across a write on native Windows. The helper publishes one complete same-directory staged record per successful call, syncs the temporary file before replacement, propagates failed writes and uses RAII cleanup of a failed staging file. Unix additionally syncs the parent. It does not offer read-modify-write transactions, last-writer ordering, cross-process coordination or a Windows power-loss durability promise. Concurrent same-target threads are possible (original 2 × 8 writer test); native settings and credential readers may verify file ownership at the same time as another call writes. The ordinary independent ACP/TUI consumers have no documented shared-target multiprocess transaction requirement; do not claim such coordination. External no-delete-sharing handles remain a supported Windows failure boundary and must not be automatically retried.
