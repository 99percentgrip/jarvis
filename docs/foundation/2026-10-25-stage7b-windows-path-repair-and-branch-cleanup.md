## Methods and red receipt

The original Windows job's install, four signed-out provider first-launch checks and uninstall emitted successful lines, then the native candidate PowerShell test's line 35 raised `installer left a changed user PATH`; no private PATH bytes were logged.
- Source-grounded cause: the protected installer read User PATH, split on semicolons, discarded empty entries and rejoined them when adding its own entry; the protected uninstaller repeated the split/filter and removed *all* equivalent entries. Both operations could change formatting or another user's duplicate. The original test compared the .NET User PATH getter, so the failure was a genuine mismatch, but did not check registry value kind or unexpanded raw value.
- Created controlled HKCU PATH regression cases within `scripts/test_install_windows.ps1`, using its existing disposable Windows hosted-runner fixture and exact raw registry snapshots: absent, present-empty, populated, leading/consecutive/trailing semicolons, duplicates, `REG_EXPAND_SZ`, pre-existing uppercase/trailing-backslash equivalent entries and equivalent duplicates, ownership metadata, upgrade retention, later appended foreign suffix and an injected staged-install failure. The test never prints PATH contents. CI's normal Windows installer job already runs this file under Windows PowerShell 5.1 and PowerShell 7; no workflow was changed.

In ordinary PR CI, run `40161291074`, job `121073212812`, reached the existing `Offline install regression (Windows PowerShell 5.1 Desktop)` step and failed after the controlled empty-value case: **`user PATH content or registry type changed: uninstall of empty`**. Earlier sentinel steps passed. The PowerShell 7 step was skipped after this failure. This is the actual vulnerable implementation failing a real Windows regression, not a model-only example.

## Focused correction and verification

- `scripts/install.ps1` now reads the unexpanded registry value and kind, appends only its token without normalizing original bytes, checks case/trailing-backslash equivalence, and records whether the value existed plus the exact insertion offset/separator for subsequent ownership-based removal and upgrades. Unsupported registry kinds refuse instead of being overwritten.
- `scripts/uninstall.ps1` removes only the recorded inserted token when it remains identifiable, retains all unrelated raw PATH bytes and the existing registry kind, and restores an originally absent value to absence. Legacy ownership metadata uses a narrower exact-trailing-token compatibility fallback rather than deleting every equivalent entry. If the recorded token cannot be safely identified after external edits, it is left unchanged rather than removing an ambiguous user entry.
- The native candidate PowerShell lifecycle test strengthens acceptance to compare raw HKCU PATH bytes, presence and registry kind; emergency restoration retains the original exception when restoration fails. The candidate acceptance Python static contract test checks this stronger restoration path.
- `PYTHONDONTWRITEBYTECODE=1 python3 -B -m unittest discover -s scripts -p 'test_*candidate_acceptance.py' -q` reported `Ran 15 tests` / `OK` / exit 0 after updating the obsolete setter-token expectation; the initial run reported one static-contract failure because the safer registry restore replaced the old .NET setter. `git diff --check` passed for the affected files.
